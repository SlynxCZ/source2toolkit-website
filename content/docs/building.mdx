title: SDK & Building
---

This guide explains how to use the **Source2Toolkit SDK** to build your own plugins.

The SDK provides everything needed to compile plugins against Source2Toolkit, including:
- KHook headers — Metamod:Source's own detour library, as the `vendor/khook` submodule, pinned to the commit Metamod was built with
- Build configuration and CMake helpers
- HL2SDK (CS2) and Protobuf — a checkout you already have, or one the SDK downloads for you

---

# Getting the SDK

Clone the SDK repository with its submodules:

```bash
git clone --recursive https://github.com/SlynxCZ/source2toolkit-sdk.git
cd source2toolkit-sdk
```

---

# Dependencies

The SDK compiles against two things it does not carry in git: **hl2sdk-cs2** (the `cs2` branch of AlliedModders' hl2sdk) and the **Protobufs** (the `csgo/` folder of SteamDatabase/Protobufs). `tools/deps.py` sets them up once and keeps them current afterwards:

```bash
python tools/deps.py init
```

`init` asks, for each of the two, whether to use a checkout you already have — found through the `HL2SDKCS2` / `CSGO_PROTO` environment variable, or a path you type — or to download it into `vendor/`. The answer is saved in `deps.json` next to the SDK (ignored by git), and from then on one command brings everything up to date the same way every time:

```bash
python tools/deps.py update
```

The full walkthrough, flags included, is on the [SDK dependencies](/docs/sdk-dependencies) page. In short: `update` pulls the two checkouts (a checkout with local changes is left alone), moves `vendor/khook` to the KHook commit that `alliedmodders/metamod-source` master pins — the toolkit core is built against that one, and a plugin built against any other KHook refuses to load — and moves `vendor/hl2sdk-manifests` to its latest. `python tools/deps.py status` shows what is configured and which commits are checked out.

The questions can be answered up front, which is what a CI script wants:

```bash
python tools/deps.py init --hl2sdk download --protobufs download
python tools/deps.py init --hl2sdk env --protobufs env
```

<Callout type="info">
  A downloaded dependency wins over the environment variable: `deps.py` writes `deps.cmake`, which CMake includes before it looks at `HL2SDKCS2` and `CSGO_PROTO`. Without `deps.json` the SDK behaves as before — the environment variables, then `vendor/hl2sdk-cs2` and `vendor/Protobufs/csgo` if they exist.
</Callout>

## By hand

If you would rather not use the script, set the two variables before running CMake:

| Variable | Description |
|---|---|
| `HL2SDKCS2` | Path to your hl2sdk-cs2 checkout |
| `CSGO_PROTO` | Path to the `csgo/` folder of a SteamDatabase/Protobufs checkout |

```bash
# Linux / macOS
export HL2SDKCS2=/path/to/hl2sdk-cs2
export CSGO_PROTO=/path/to/Protobufs/csgo

# Windows (PowerShell)
$env:HL2SDKCS2 = "C:\path\to\hl2sdk-cs2"
$env:CSGO_PROTO = "C:\path\to\Protobufs\csgo"
```

KHook needs nothing from you: it is the `vendor/khook` submodule. `MMSOURCE_DEV` is only read when building the toolkit core itself.

# Project Setup

A typical plugin project using the SDK looks like this:

```
my-plugin/
├── CMakeLists.txt
├── src/
│   └── plugin.cpp
└── vendor/
    └── source2toolkit-sdk/
```

---

# CMake Configuration

To use the SDK, include it as a subdirectory and use the provided helper function.

```cmake
cmake_minimum_required(VERSION 3.18)
project(my-plugin CXX)

set(CMAKE_CXX_STANDARD 20)

add_subdirectory(vendor/source2toolkit-sdk)

add_s2toolkit_plugin(my_plugin
    src/plugin.cpp
)
```

<Callout type="tip">
  The <code>add_s2toolkit_plugin</code> function automatically configures linking, include paths, and output format.
</Callout>

# Example Plugin

Below is a minimal working plugin using the SDK:

```cpp
#include "source2toolkit/IToolkitPlugin.h"
#include "source2toolkit/utils/log.h"

class Plugin final : public IToolkitPlugin
{
public:
    bool Load(PluginId id, IToolkitAPI* api, char* error, size_t maxlen, bool late) override
    {
        TOOLKIT_SAVEVARS();
        api->AddListener(this, this);
        TOOLKIT_LOG(this, "Hello World! Plugin loaded.\n");
        return true;
    }

    bool Unload(char*, size_t) override
    {
        TOOLKIT_LOG(this, "Plugin unloaded.\n");
        return true;
    }

private:
    const char* GetName() override { return "My Plugin"; }
    const char* GetVersion() override { return "1.0.0"; }
    const char* GetAuthor() override { return "You"; }
    const char* GetDescription() override { return "My first plugin"; }
};

Plugin g_Plugin;
TOOLKIT_EXPOSE(my_plugin, g_Plugin);
```

---

# Building the Plugin

```bash
mkdir build && cd build
cmake ..
cmake --build . --config Release
```

After building, you will get:

```
my_plugin.stx
```

---

# Output

The compiled plugin uses the `.stx` extension and is ready to be placed into:

```
/game/csgo/addons/source2toolkit/plugins/
```

# What the SDK Handles

The SDK automatically configures:

- Platform-specific compiler flags
- Linking against HL2SDK and engine libraries
- Protobuf integration
- ABI compatibility (Linux / Windows)
- Include directories for Source 2 and KHook headers
- Plugin output format (`.stx`)

---

# Platform Notes

## Linux

- Uses static linking for standard libraries
- Enforces `_GLIBCXX_USE_CXX11_ABI=0`

## Windows

- Requires **MSVC compiler**
- MinGW is not supported

---

# Summary

Using the SDK is simple:

```cmake
add_subdirectory(source2toolkit-sdk)

add_s2toolkit_plugin(my_plugin
    src/plugin.cpp
)
```

Run `python tools/deps.py init` once (or set `HL2SDKCS2` and `CSGO_PROTO` yourself), then build — that's it.
