title: Event Reference

The fields below are taken from the event definitions CS2 ships in its VPKs —
`resource/core.gameevents` (engine), `resource/game.gameevents` and
`resource/mod.gameevents` (Counter-Strike). Where an event is defined in more
than one file, the most specific definition is listed — `mod` over `game` over
`core`. Names are case sensitive.

For hooking, reading and firing, see [Game events](/docs/events/game-events).

## Field types and getters

| Type in the definition | Read with |
| --- | --- |
| `player_controller_and_pawn` | `GetPlayerController(key)`, `GetPlayerPawn(key)`, `GetPlayerSlot(key)` |
| `player_controller` | `GetPlayerController(key)`, `GetPlayerSlot(key)` — the pawn through the controller |
| `player_pawn` | `GetPlayerPawn(key)` |
| `bool` | `GetBool(key)` |
| `byte`, `short`, `long` | `GetInt(key)` |
| `float` | `GetFloat(key)` |
| `string` | `GetString(key)` |
| `uint64` | `GetUint64(key)` |

Player getters return a `CEntityInstance*`; `static_cast` it to
`CCSPlayerController*` / `CCSPlayerPawn*` and check for `nullptr`.

```cpp
auto* pController = static_cast<CCSPlayerController*>(event->GetPlayerController("userid"));
CCSPlayerPawn* pPawn = pController ? pController->GetPlayerPawn() : nullptr;
```

## Client-only helpers

| Event | Fields | Use |
| --- | --- | --- |
| `show_survival_respawn_status` | `loc_token` (string), `duration` (long), `userid` (player_controller_and_pawn) | HTML text in the centre of the screen — what `CCSPlayerController::PrintToCenterHtml` sends. |

## Finding other events

The full definitions are plain text inside the game's VPKs:
`game/csgo/pak01_dir.vpk` → `resource/game.gameevents` and
`resource/mod.gameevents`, `game/core/pak01_dir.vpk` →
`resource/core.gameevents`. Any VPK tool can open them. To see what fires in
practice, hook the candidates with a post hook that logs `event->GetName()`.
