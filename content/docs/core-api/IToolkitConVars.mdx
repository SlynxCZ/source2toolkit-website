---
title: "IToolkitConVars"
description: "Interface for managing and interacting with console variables (ConVars)."
---


Provides functionality for:
- Querying ConVars by name
- Reading and writing values
- Accessing metadata (type, flags, help text)
- Creating and deleting ConVars

<Callout type="info">ConVars are identified by an internal access index.</Callout>

**Interface id** `IToolkitConVars002` (`TOOLKIT_CONVARS_INTERFACE`) · **Global** `g_pToolkitConVars` · **Header** [`source2toolkit/IToolkitConVars.h`](https://github.com/Source2Toolkit/source2toolkit-sdk/blob/main/public/source2toolkit/IToolkitConVars.h)

### `HookConVarChange`

```cpp
virtual ToolkitHookId HookConVarChange(ConVarChangeHandler handler) = 0;
```

Registers a listener for every ConVar value change.

The engine only takes plain function pointers here, and only keeps one list of them for the whole process. The toolkit installs a single one of those and fans out to the handlers registered through this, so a plugin can use a capturing lambda and does not have to unregister on unload.

A plugin may register as many as it likes.

Whose it is, the core reads off the handler (see ToolkitCallback); what a plugin still holds at unload the core drops for it.

| Parameter | Type | Description |
|---|---|---|
| `handler` | [`ConVarChangeHandler`](/docs/core-api/IToolkitConVars#convarchangehandler) | A function, an object and a method, or a lambda |

**Returns** [`ToolkitHookId`](/docs/core-api/IToolkitTypes#toolkithookid) — The id UnhookConVarChange(id) takes

### `UnhookConVarChange`

```cpp
virtual bool UnhookConVarChange(const ConVarChangeHandler& handler) = 0;
virtual bool UnhookConVarChange(ToolkitHookId id) = 0;
```

Drops the change listener with this handler -- a function or an object and a method; a lambda goes by its id.

Drops the change listener HookConVarChange() returned the id for.

| Parameter | Type |

**Returns** `bool` — true when one was found

### `CreateConVar`

```cpp
virtual uint16 CreateConVar(const char* name, EConVarType type, const char* help, uint64 flags, bool hasMin, bool hasMax, void* defaultValue, const void* minValue, const void* maxValue) = 0;
```

Creates a new ConVar.

<Callout type="info">The engine has no way to unregister a ConVar, so one created here outlives the plugin that created it. When the plugin loads again, the same call returns the existing ConVar with its current value.</Callout>

| Parameter | Type | Description |
|---|---|---|
| `name` | `const char*` | ConVar name |
| `type` | `EConVarType` | Variable type |
| `help` | `const char*` | Description text |
| `flags` | `uint64` | FCVAR flags |
| `hasMin` | `bool` | Whether min value is enforced |
| `hasMax` | `bool` | Whether max value is enforced |
| `defaultValue` | `void*` | Default value pointer (const char* for EConVarType_String) |
| `minValue` | `const void*` | Minimum value pointer; only read when hasMin is true, may be nullptr otherwise |
| `maxValue` | `const void*` | Maximum value pointer; only read when hasMax is true, may be nullptr otherwise |

**Returns** `uint16` — Access index of the created ConVar. If a ConVar with that name already exists, its index is returned and the arguments are ignored. TOOLKIT_INVALID_CONVAR_INDEX on bad arguments or an unsupported type.
