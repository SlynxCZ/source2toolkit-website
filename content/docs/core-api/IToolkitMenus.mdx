Provides functionality for:
- Defining menus and menu options
- Handling per-player menu instances
- Processing menu navigation and input

Interface for menu system management.

### `OpenCenterHtmlMenu`

```cpp
virtual void OpenCenterHtmlMenu(PluginId owner, CCSPlayerController* player, CenterHtmlMenu* menu) = 0;
```

Opens a CenterHtmlMenu for a player.

<Callout type="info">Closed for you if the owning plugin unloads while it is open. The menu object and its option handlers live inside that plugin's library, and the next key press would go looking for them there.</Callout>

### `OpenMenu`

```cpp
virtual void OpenMenu(PluginId owner, CCSPlayerController* player, IMenuInstance* instance) = 0;
```

Opens a menu instance another library built.

The instance is drawn, refreshed (OnFrame) and fed the keys by the core like its own, and Destroy()ed when closed, replaced, the player leaves or `owner` unloads. This is how the CustomhudManager_s2t plugin serves its HudMenu (ICustomhudManager::OpenMenu); a plugin with a screen of its own can do the same.

| Parameter | Type | Description |
|---|---|---|
| `owner` | [`PluginId`](/docs/core-api/IToolkitApi#pluginid) | Plugin the menu belongs to (whose unload closes it) |
| `player` | [`CCSPlayerController*`](/docs/schema/entity/classes/CCSPlayerController) | Target player |
| `instance` | [`IMenuInstance*`](/docs/core-api/IToolkitMenus#imenuinstance) | Built with new by the caller; the core owns it from here |


Closes the menu.

### `OnFrame`

```cpp
virtual void OnFrame();
```

Once a frame while this is the player's open menu.

The default redraws, which is what a center HTML menu needs (it fades). A menu drawn on a HUD layout overrides it to refresh only when something changed.

### `AcceptsKeys`

```cpp
virtual bool AcceptsKeys() const;
```

Whether the number keys (chat triggers, binds) pick options.

A menu the player clicks instead returns false and the core drops the key presses while it is open.

### `Destroy`

```cpp
virtual void Destroy();
```

Destroys the instance.

The core calls this, never delete, when the menu is closed, replaced or the player leaves -- so an instance a plugin built (OpenMenu) is freed by the library that allocated it.
