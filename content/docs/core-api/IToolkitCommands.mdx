Provides functionality for:
- Registering console commands
- Listening to console command execution
- Handling in-game chat messages

<Callout type="info">This system allows plugins to hook into player input via chat or console.</Callout>

Interface for registering and handling commands.

Supports:
- Chat-based commands (player messages)
- Console commands (server or client)
- Command listeners with pre/post execution hooks

<Callout type="info">Every registration belongs to the plugin whose handler it is.</Callout>

**Interface id** `IToolkitCommands003` (`TOOLKIT_COMMANDS_INTERFACE`) · **Global** `g_pToolkitCommands` · **Header** [`source2toolkit/IToolkitCommands.h`](https://github.com/Source2Toolkit/source2toolkit-sdk/blob/main/public/source2toolkit/IToolkitCommands.h)

## Methods

### `RegisterChatListener`

```cpp
virtual ToolkitHookId RegisterChatListener(const char* pchName, ChatHandler handler, const char* pchPermission = nullptr) = 0;
```

Registers a chat command.

Only fires for a chat message that starts with one of the configured chat triggers (public or silent, "!" and "/" by default), e.g. "!kick" or "/kick"; plain "kick" typed into chat does not fire it. The trigger is stripped before matching, so args.Arg(0) is the bare name. A silent trigger hides the message; a public one lets it show.

Whose it is, the core reads off the handler (see ToolkitCallback); what a plugin still holds at unload the core drops for it.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `pchName` | `const char*` |  | Command name without a trigger (e.g. "kick") |
| `handler` | [`ChatHandler`](/docs/core-api/IToolkitCommands#chathandler) |  | A function, an object and a method, or a lambda |
| `pchPermission` | `const char*` | `nullptr` | What a player needs to run it (see IToolkitPermissions); nullptr or "" for everybody. A player without it gets the access-denied answer instead. |

**Returns** [`ToolkitHookId`](/docs/core-api/IToolkitTypes#toolkithookid) — The id UnregisterChatListener(id) takes

### `RegisterConListener`

```cpp
virtual ToolkitHookId RegisterConListener(const char* pchName, CommandHandler handler, bool post) = 0;
```

Registers a listener on an existing console command.

The handler's Action:
- Ignore: do nothing
- Override: the original still runs; commands return nothing, so this has no further effect. Later pre listeners and all post listeners still fire.
- Supersede: block the original (pre only); the remaining pre listeners and all post listeners are skipped

Whose it is, the core reads off the handler (see ToolkitCallback); what a plugin still holds at unload the core drops for it.

| Parameter | Type | Description |
|---|---|---|
| `pchName` | `const char*` | Existing command name to listen for |
| `handler` | [`CommandHandler`](/docs/core-api/IToolkitCommands#commandhandler) | A function, an object and a method, or a lambda |
| `post` | `bool` | false to run before the original, true to run after |

**Returns** [`ToolkitHookId`](/docs/core-api/IToolkitTypes#toolkithookid) — The id UnregisterConListener(id) takes

## Enums

| Name | Description |
|---|---|
