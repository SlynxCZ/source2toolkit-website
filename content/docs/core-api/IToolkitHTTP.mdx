---
title: "IToolkitHTTP"
description: "Interface for HTTP requests."
---


Requests go out through Steam's own HTTP client, which the game server already has, so there is no curl to link and nothing to pump. Steam only hands that client over once the API has activated, which happens after level startup -- requests made before then are queued and sent when it does, so a plugin does not have to care whether it is early.

Responses come back on the main thread.

Issues HTTP requests through Steam's HTTP client.

```cpp
HTTP_GET("https://example.com/api", [](const ToolkitHTTPResponse& r)
{
    if (!r.m_bSuccess || r.m_nStatusCode != 200)
        return;

    // r.m_sBody -- parse with whatever your plugin already uses.
});
```

**Interface id** `IToolkitHTTP002` (`TOOLKIT_HTTP_INTERFACE`) · **Global** `g_pToolkitHTTP` · **Header** [`source2toolkit/IToolkitHTTP.h`](https://github.com/Source2Toolkit/source2toolkit-sdk/blob/main/public/source2toolkit/IToolkitHTTP.h)

## Methods

### `IsAvailable`

```cpp
virtual bool IsAvailable() const = 0;
```

Whether Steam's HTTP client is available yet.

Requests made while this is false are queued, not dropped, so checking is only worth it to avoid building a body you cannot send.

### `PendingCount`

```cpp
virtual int PendingCount() const = 0;
```

Number of requests waiting for Steam's HTTP client.

### `Request`

```cpp
virtual void Request(EToolkitHTTPMethod method, const char* pszUrl, const char* pszBody, ToolkitHTTPCallback callback, const std::vector<ToolkitHTTPHeader>* pHeaders = nullptr) = 0;
```

Issues a request.

The plugin the callback's code lies in owns the request.

<Callout type="info">Cancelled, callback and all, if the owning plugin unloads first -- the callback holds code inside that plugin's library.</Callout>

| `callback` | [`ToolkitHTTPCallback`](/docs/core-api/IToolkitHTTP#toolkithttpcallback) |  | Called once the request completes; may be null |

## `ToolkitHTTPResponse`

What a completed request came back with.

<Callout type="info">m_bSuccess is about the transport, not the status code -- a 404 that arrived is a success with m_nStatusCode == 404. A request that never completed has m_bSuccess false and m_nStatusCode 0.</Callout>
