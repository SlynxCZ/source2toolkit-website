Source2Toolkit is a Metamod:Source plugin, so a server needs Metamod first and the toolkit on top of it. Both are folders you copy into `game/csgo/`. Linux and Windows servers are both supported.

## Prerequisites

- A Counter-Strike 2 dedicated server you can restart and reach the console of.
- [Metamod:Source 2.x](https://www.metamodsource.net/downloads.php?branch=dev) — a current dev build, matching your OS.
- The latest [Source2Toolkit release](https://github.com/Source2Toolkit/source2toolkit/releases) — `source2toolkit_<version>-linux.tar.gz` or `source2toolkit_<version>-windows.tar.gz`.

<Callout type="warn">
  CS2 updates regularly break older Metamod builds. When the server stops loading Metamod after a game update, update Metamod before looking anywhere else.
</Callout>

## Install Metamod:Source

<Steps>
<Step>

Download the Metamod:Source build for your operating system and extract it.

</Step>
<Step>

Copy its `addons/` folder into your server's `game/csgo/` folder, so that you end up with `game/csgo/addons/metamod/`.

</Step>
<Step>

Open `game/csgo/gameinfo.gi`, find the line

```
Game_LowViolence	csgo_lv // Perfect World content override
```

and add this line **below** it:

```
Game	csgo/addons/metamod
```

</Step>
<Step>

Start the server and run `meta list` in its console. If the command is known, Metamod is loaded.

</Step>
</Steps>

<Callout type="info">
  Game updates overwrite `gameinfo.gi`. If Metamod disappears after an update, the `Game csgo/addons/metamod` line is the first thing to check.
</Callout>

## Install Source2Toolkit

<Steps>
<Step>

Download the release archive for your operating system and extract it. It contains a single `addons/` folder.

</Step>
<Step>

Copy that `addons/` folder into `game/csgo/`, merging it with the one Metamod created.

</Step>
<Step>

Restart the server. The toolkit has to be loaded at server start: loading it later with `meta load` is refused (`Late load is not supported`).

</Step>
</Steps>

### What the release contains

```
game/csgo/addons/
├── metamod/
│   └── source2toolkit.vdf          # tells Metamod to load the toolkit
└── source2toolkit/
    ├── bin/
    │   └── linuxsteamrt64/          # win64/ in the Windows archive
    ├── configs/
    │   └── core.example.json        # template for core.json
    ├── gamedata/
    │   └── gamedata.json            # the core's signatures and offsets
    ├── plugins/                     # your .stx plugins go here
    ├── shared/                      # data more than one plugin reads
    └── dumps/                       # crash dumps land here
```

| Folder | What it is for |
|---|---|
| `bin/` | The toolkit core binary. |
| `configs/` | `core.json`, `permissions.json` (admins and groups, see [Permissions](/docs/guides/permissions)), and one `configs/<PluginName>/` folder per plugin for its own config files (`PLUGIN_CONFIG_DIR()`). |
| `gamedata/` | Every `.json` file here is loaded at start. Plugins that need signatures of their own ship an extra file next to `gamedata.json` — see [Gamedata](/docs/development/gamedata). |
| `plugins/` | Every `.stx` file here is loaded at start. |
| `shared/` | Data files read by more than one plugin (`TOOLKIT_SHARED_DIR()`). |
| `dumps/` | Minidumps and crash reports written by the [crash handler](/docs/guides/crash-handler). |

Missing folders are created on start, so deleting an empty one does no harm.

## Core configuration

On its first start the core copies `configs/core.example.json` to `configs/core.json` and reads that from then on. Releases only ship the example, so updating the toolkit never overwrites your settings.

```json title="configs/core.json"
{
  "PublicChatTrigger": [ "!" ],
  "SilentChatTrigger": [ "/" ],
  "PluginHotReloadEnabled": true,
  "PluginAutoLoadEnabled": true,
  "UnlockConCommands": true,
  "UnlockConVars": true,
  "CrashHandlerEnabled": true,
  "CrashDiscordWebhook": "",
  "SlowCallbackWarnMs": 100,
  "SteamAuthMode": "auto",
  "AccessDeniedMessage": "You do not have access to this command."
}
```

The file may contain `//` and `/* */` comments.

| Key | Default | Meaning |
|---|---|---|
| `PublicChatTrigger` | `["!"]` | Chat prefixes that run a command. `!mycommand` runs the plugin command `mycommand` and the message still shows in chat. |
| `SilentChatTrigger` | `["/"]` | Same, but the chat message is suppressed. |
| `PluginHotReloadEnabled` | `true` | Linux only: reload a plugin when its `.stx` is rewritten. See [Plugin lifecycle](/docs/development/plugin-lifecycle#hot-reload). |
| `PluginAutoLoadEnabled` | `true` | Load every `.stx` in `plugins/` at start. When `false`, nothing loads until you run `toolkit refresh` or `toolkit load`. |
| `UnlockConCommands` | `true` | Remove `FCVAR_HIDDEN` and `FCVAR_DEVELOPMENTONLY` from every console command, so hidden commands can be used. |
| `UnlockConVars` | `true` | The same for ConVars. |
| `CrashHandlerEnabled` | `true` | Install the crash handler. |
| `CrashDiscordWebhook` | `""` | Discord webhook URL for crash reports. Empty disables Discord reporting; dumps are still written. |
| `SlowCallbackWarnMs` | `100` | A plugin callback that takes longer than this is logged with its name and plugin — see [Compatibility](/docs/development/compatibility#when-the-server-stalls). `0` turns it off. |
| `SteamAuthMode` | `"auto"` | Which SteamID a player's [permissions](/docs/guides/permissions#which-steamid-counts) are looked up under: `"auto"`, `"flexible"` or `"strict"`. |
| `AccessDeniedMessage` | `"You do not have access to this command."` | What a player is told when refused a command, unless a plugin set its own answer. |

The file is read once, when the core loads. Restart the server after changing it.

## Installing plugins

Copy a plugin's `.stx` file into `addons/source2toolkit/plugins/`. If it comes with configs, gamedata or shared data, those go into `configs/`, `gamedata/` and `shared/` as its instructions say.

On a running server, `toolkit refresh` loads every `.stx` in `plugins/` that is not loaded yet; a new gamedata file, however, is only read when the server restarts.

One plugin most servers want: [**CustomhudManager_s2t**](https://github.com/SlynxCZ/CustomhudManager_s2t/releases), the Panorama HUD — menus on the HUD, on-screen texts, toasts, timers. Plugins that draw on the HUD ask for its interface at load; without it they draw nothing. Its players need the addon described in [HUD menus, texts and prompts](/docs/panorama/hud#the-addon).

## Verifying the installation

Run `meta list` in the server console. **Source2Toolkit** should be in the list of Metamod plugins.

Then ask the toolkit itself. The console command is `toolkit` (with the aliases `st`, `s2t`, `s2toolkit`, `stoolkit`, `source2t` and `source2toolkit`):

```
toolkit version
toolkit list
```

| Command | What it does |
|---|---|
| `toolkit list` | Lists loaded plugins as `[id] name (version) by author`, with a second line per plugin: its plugin API version, the KHook commit it was built against and its tier — *stable* (no KHook hooks of its own: a game or KHook change needs only a core update) or *raw* (rebuild). See [Compatibility](/docs/development/compatibility). |
| `toolkit info <id>` | Name, version, author, description, file path, plugin API, KHook commit, how many hooks of its own it declared, and every toolkit interface (with revision) it asked for. |
| `toolkit load <name>` | Loads the first `.stx` in `plugins/` whose file name contains `<name>`. |
| `toolkit unload <id>` | Unloads a plugin by the id `toolkit list` shows. |
| `toolkit refresh` | Loads every `.stx` in `plugins/` that is not loaded yet. |
| `toolkit version` | Toolkit version, plugin API version, build date and commit. |
| `toolkit credits` | Who made it. |

`load`, `unload` and `refresh` work only from the server console (or RCON). Players can run `list`, `info`, `version` and `credits` from their own console.

## When something does not load

- **Source2Toolkit is not in `meta list`** — Metamod is not loading it. Check that `addons/metamod/source2toolkit.vdf` exists and that the `bin/` folder for your OS is there.
- **A plugin is missing from `toolkit list`** — the core prints why at start: `Plugin <name> refused to load: <reason>` or `Failed to load <path>: <reason>`, followed by a summary line with the number that failed. A `KHook mismatch` reason means the plugin was built against a different KHook than the core runs; see the [FAQ](/docs/resources/faq#a-plugin-refuses-to-load-with-khook-mismatch).
- **The server crashes on start** — see the [crash handler guide](/docs/guides/crash-handler); the report on the next start names the module that crashed.
