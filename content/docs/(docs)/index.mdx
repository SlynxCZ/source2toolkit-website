Source2Toolkit is a server-side development toolkit for **Counter-Strike 2**. It gives C++ plugins direct access to Source 2 internals — the schema system, entities, hooks, memory, network messages — together with the high-level pieces every server plugin needs: commands, ConVars, game events, menus, timers, HTTP, MySQL and more.

## Who it is for

- **Plugin developers** who want native C++ with no scripting layer or managed runtime in between, and who are comfortable reading engine code when they need to.
- **Server owners** who run plugins built on the toolkit: installing it is a Metamod plugin plus a folder of `.stx` files.

## How it fits with Metamod:Source

Source2Toolkit is itself a **Metamod:Source plugin**. Metamod loads the toolkit core (`addons/source2toolkit/bin/...`), and the core then loads your plugins — `.stx` files from `addons/source2toolkit/plugins/` — and hands each of them the toolkit API.

That split is deliberate:

- Your plugin talks to one API (`IToolkitAPI` and the `g_pToolkit*` interfaces) instead of fetching engine interfaces, scanning signatures and wiring listeners itself.
- Everything a plugin registers — commands, event hooks, timers, net message hooks, menus — is owned by its plugin id and removed when the plugin unloads.
- Hooks use **KHook**, the detour library inside Metamod:Source. Metamod, the toolkit and every toolkit plugin share one KHook instance, so hooks placed by different plugins on the same function chain correctly.

The core also resolves engine functions from a shared gamedata folder, so most plugins never ship a signature of their own.

## Features

### Engine access

- **Schema system** — generated classes for the game's schema (`CBaseEntity`, `CCSPlayerController`, …) with typed field access and network state updates.
- **Entities** — find, create and spawn entities, entity listeners and entity I/O.
- **Hooks** — KHook virtual, vtable and function detours, declared in one line with `KHOOK_VIRTUAL` / `KHOOK_MEMBER` / `KHOOK_FUNCTION`.
- **Addresses** — engine functions the core already resolved (spawn, take damage, set model, switch team, …), ready to call through `ADDR_*()`.
- **GameConfig** — signatures, offsets and patches from JSON gamedata, per platform.
- **Memory & modules** — pattern scans, symbol lookups and typed casts on any loaded library.
- **Game systems** — register your own `IGameSystem` on the engine's factory list.

### Gameplay

- **Commands** — console and chat commands, plus listeners on commands you do not own.
- **[Permissions](/docs/guides/permissions)** — admins, groups and dotted permissions from a file or granted at runtime, commands gated by them.
- **ConVars** — declare your own, read and write the game's, hear about changes.
- **Game events** — pre/post hooks with field access, `dontBroadcast` and cancel, and firing your own.
- **Network messages** — allocate, send and hook Source 2 net messages by id or by name.
- **Menus** — chat menus with per-player state.
- **Custom HUD** — Panorama layouts with click callbacks.
- **Scheduler** — timers and next-frame tasks.
- **Tracing** — ray and hull traces for line-of-sight and collision queries.
- **Sounds** — sound events for exactly the players you pick, stop and change by guid, per-player volume channels and a hook on every sound the game sends.
- **Transmit** — per-viewer entity visibility, owner-following and a CheckTransmit hook.
- **[Scripts](/docs/guides/scripts)** — run cs_script (compiled assets, raw source, hot-reloaded files), fire inputs into a script and receive its messages.

### Services

- **HTTP** — asynchronous requests through Steam's HTTP client.
- **JSON** — parse and build JSON without a dependency of your own.
- **MySQL** — queries with typed result sets.
- **Paths** — the game directory, the toolkit root, configs, gamedata, plugins and a shared data folder.
- **[Crash handler](/docs/guides/crash-handler)** — minidumps processed on the server itself, plugin frames symbolized to `function @ file:line`, a suspected culprit and an optional Discord report.
